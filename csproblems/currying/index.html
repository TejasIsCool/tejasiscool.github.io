So, what is currying???

Let me talk a little bit about types first. Types are, in some sense, a classification of objects.
For now, we will assume types as basically the same as sets. Types are a bit different. There is a notion that one object cannot belong to multiple types. But in sets, one object can be part of many sets. We won't be covering anything related to that in this page, so for our purpose, types are basically sets. If you are interested, check this out. I myself am not very knowledgeable on type theory, so if there is an error here, let me know.
Any object of certain type, in haskell is denoted like 

            a :: Integer
            a = 2       -- Things after -- are comments.
This means, we are saying that the variable a is of type Integer (ie, contained in the Integer set) denoted by a :: Integer, and the line after is the definition of a, which we are saying is 2. A function f : A \to B is something, which for every element of type A, associates exactly one element of type B. In haskell, we could write it like 

            f :: Integer -> Integer
            f x = x*x
In usual sense, in the type Integer -> Integer, the first Integer denotes input input type, and the second one denotes the output type. And in the definition, variables on the left of the =, are the names of the input the function f is taking in, and on the right, is what the function f will output. I'll now show you another example. 

            f :: Integer -> Integer
            f x = x*x  -- As defined above

            g :: Integer -> Integer
            g = f
Observe, that g looks like it is not taking in any input, and is returning the function f !!! We can think of it, as renaming the function f to g here. So g becomes just another name for f. If I ask you what is g 2 (giving the number 2 to g as input), it seems obvious to give that input to f, evaluate it, and return back. And in this case, we would get the output as 4. 
            
                g 2
                4
(ghci is haskell's interactive code runner) In some sense, when we write g :: Integer -> Integer To make it valid haskell, the definition of g must produce something of the type Integer -> Integer. And we achieved that by return the function f here. Point being that functions themselves can be though of as values, they can be named into a variable, returned or passed around. I'll tell you the significance of this observation in a bit. Lets try to make a function that takes in two inputs. 

            f2 :: Integer -> Integer -> Integer
            f2 x y = x*y
This seems like a strange way of writing this. Why is there an arrow between the first two Integers when we are giving the type? Set theoretically, it makes more sense like  f2: (Integer × Integer) \to Integer I'll get to this in a bit as well. Just go with it for now. So f2 :: Integer -> Integer -> Integer is somewhat indicating that the first two Integers are the inputs, and the third Integer is the output type. But, like above, there are more things that can satisfy the same type. 

            f :: Integer -> Integer
            f x = x*x 

            f2 :: Integer -> Integer -> Integer
            f2 x y = x*y

            g2 :: Integer -> Integer -> Integer
            g2 = f2 -- Similar logic to g above.

            h2 :: Integer -> Integer -> Integer
            h2 z = f
Hey! Whats going on with the last example?! In haskell, the arrows in the function type are right-associative, ie, by default, h2 :: Integer -> Integer -> Integer is read as h2 :: Integer -> (Integer -> Integer) and not h2 :: (Integer -> Integer) -> Integer So h2 is taking as input an integer, and returning something of type (Integer \to Integer), ie, a function! In the specific case above, it completely ignores the inputted z, and just returns the function f. So functions can return functions, as long as the types work. They can also take in functions as input too! 

            h4 :: (Integer -> Integer) -> Integer
            h4 a = a 2
Since haskell is right associative on function type arrows, we have to put the brackets there. Here, it is inputting a function a, of type (Integer \to Integer), and as an output, it is returning an Integer. See if you can see how, and try to guess the output of h4 f, (f defined in above code block). Back to currying. Why did we denote the type of taking in two inputs as f2 :: Integer -> Integer -> Integer? If we take the right associativity of function type arrows, this would mean that f2 :: Integer -> (Integer -> Integer). But we can see it taking two inputs above! Why not have something like? 

            f2 :: (Integer × Integer) -> Integer -- Not valid haskell code!
            f2 (x,y) = x*y
Well, you can! The syntax/way of writing is a bit different, but 

            f2' :: (Integer, Integer) -> Integer
            f2' (x,y) = x*y
works! The (Integer, Integer) represents all pairs of Integers as a tuple. So why f2 :: Integer -> (Integer -> Integer)? Here, let me show you something cool. with the definition as 

            f2 :: Integer -> Integer -> Integer
            f2 x y = x*y
What happens if we only give one input to it, as the right associativity of function typing would suggest? 
            
                f2 3
                <interactive>:13:1: error: [GHC-39999]
                • No instance for ‘Show (Integer -> Integer)’
                    arising from a use of ‘print’
                    (maybe you haven't applied a function to enough arguments?)
                • In a stmt of an interactive GHCi command: print it
An error... But looking more carefully, this isin't a logical or syntax error, but an error indicating that haskell could not print the output. Reading even more carefully, it says has no instance of "Show (Integer -> Integer)", which means haskell does not know how to show something of the type Integer -> Integer. But where did that come from? Lets see what the type of f2 3 is. 
            
                :t (f2 3) -- :t gives the type of an object
                (f2 3) :: Integer -> Integer
So f2 3 is a function?! Yes. Lets see what happens if we use it as a function, and give it another input. 
            
                (f2 3) 7
                21
So its working as it was defined, just that the inputs were given in a strange manner. This notion, of having a multi-input function, being converted to a function giving another function on one input, is called currying. This is what is kind of happening internally when we write the function definition. 

            f2 :: Integer -> Integer -> Integer
            f2 x y = x*y

            -- Is essentially
            f2_internal :: Integer -> Integer -> Integer
            f2_internal x = partial_f where
                partial_f y = x * y
            -- 'where' allows us to define a function or variables in body of another function.
And when we write f2 3 7, that is run as (f2 3) 7 (This suggests that function application is left associative! Ie, brackets happen like (f2 3) 7 and not f2 (3 7)) This is true for all multi-input functions in haskell! The way haskell works is by considering every multi-input function as a single input function, which takes in one input, and returns a function, which can take another input and so on. The inputs which have already been taken, stay in the scope of the internal function. Above, partial_f is able to access the variable x, even though it does not explicitly take it as an input.
So, more explicitly (copied from wikipedia): Currying is the technique of translating a function that takes multiple arguments, into a sequence of families of functions, each taking a single argument. (Ie, converting from multiple input function, to functions which take in one input, and give out another function which can take another input, and so on). So instead of taking inputs as pairs/tuples, you can take them one by one. When you only give some of the inputs to the function, that is called partial application of the function. Actually though, both styles of taking inputs are essentially same/equivalent/isomorphic/similar. By that, I mean that you can show a bijection between all functions of type f :: (Integer, Integer) \to Integer and of type g :: Integer \to (Integer \to Integer). In maths notation, this means for any three sets A, B, C C^{A × B} \cong (C^B)^A}. Where, for sets X,Y, Y^X = \{Set of all functions from X to Y}. And X \cong Y means |X| = |Y|, ie, ∃ bijection from X \to Y here.
Why is Y^X the notation of all functions from X to Y? Suppose X and Y were two finite sets, with cardinality |X| and |Y|.
Can you count the number of functions from X to Y?
I will leave it as an exercise for you to show this bijection. And this is why we write the type as Integer -> Integer -> Integer when taking in two inputs, as it is equivalent to taking it as a pair. While simultaneously allowing us to partially give the inputs as well. Infact, haskell itself gives this bijection to you, via its curry function, and its inverse uncurry. 
            
                :t curry
                curry :: ((a, b) -> c) -> a -> b -> c
                :t uncurry
                uncurry :: (a -> b -> c) -> (a, b) -> c
                :t f2
                f2 :: Integer -> Integer -> Integer
                :t (uncurry f2)
                (uncurry f2) :: (Integer, Integer) -> Integer
                (uncurry f2) (3,4)   
                12
                :t curry (uncurry f2)
                curry (uncurry f2) :: Integer -> Integer -> Integer
(The a,b,c in lowercase stand for any arbitrary type, indicating that curry and uncurry work for all types of objects.) Try making your own curry and uncurry function in haskell using the bijection in the exercise above.
